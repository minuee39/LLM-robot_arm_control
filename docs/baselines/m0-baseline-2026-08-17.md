## 작업 중 발생한 문제

### 문제 1: Python package metadata 불일치

- 문제: `.venv/bin/python -m pip check` 실패
- 원인: `opencv-contrib-python==4.11.0.86`은 설치되어 있지만 `ultralytics==8.4.82`가 package metadata상 `opencv-python`을 요구한다.
- 현재 처리: 실제 환경 snapshot과 충돌을 모두 기록했다. 무리하게 OpenCV wheel을 중복 설치하지 않는다.
- 후속 해결: Python packaging 단계에서 OpenCV 배포판을 하나로 통일하고 ROS/Isaac ABI를 각각 검증한다.

핵심 로그:

```text
ultralytics 8.4.82 requires opencv-python, which is not installed.
```

### 문제 2: MTC build의 stale NumPy include

- 문제: `mtc_tutorial` CMake generate 실패
- 원인: 기존 `moveit_task_constructor_core` install export가 삭제된 user-site NumPy include 경로를 참조한다.
- 영향: `isaac_moveit_bridge`, description, MoveIt config는 빌드됐지만 `mtc_tutorial`은 재구성이 필요하다.
- 후속 해결: MTC dependency를 고정 환경에서 다시 빌드하고 user-site가 아닌 활성 Python NumPy include를 사용하도록 underlay를 재생성한다.

핵심 로그:

```text
Imported target moveit_task_constructor_core_stages includes non-existent path:
/home/minwoo/.local/lib/python3.10/site-packages/numpy/core/include
```

### 문제 3: 기존 Python 테스트 2건

- socket test: Codex sandbox가 TCP socket 생성을 차단해 실패
- MTC size test: 현재 BLOCK_SIZE와 기존 `object_size_z:=0.100000` 기대값이 불일치
- 후속 처리: BLOCK_SIZE·PlanningScene·테스트 기대값 통일 항목에서 해결한다.

## 최종 구조와 설계 결정

1. 메인 Git은 프로젝트 전용 코드와 기준 문서만 관리한다.
2. 외부 ROS source는 URL과 SHA를 `.repos`에 고정한다.
3. 기존 vendored dependency는 후속 정리 전까지 version과 content hash로 식별한다.
4. Python, Isaac Sim, ROS 2, REMIND 환경을 서로 분리한다.
5. 모델 weight와 데이터셋은 Git에서 제외하고 SHA256 manifest만 추적한다.
6. 실패가 있는 상태도 숨기지 않고 기준선에 기록하며, 이후 변경은 이 결과와 비교한다.

## 실패 처리

- manifest에 없는 외부 source나 model은 canonical 실행에 사용하지 않는다.
- dependency version이 바뀌면 baseline tag를 덮어쓰지 않고 새 기준선을 만든다.
- 모델 hash가 다르면 실행을 중지하고 출처를 확인한다.
- 실제 로봇에는 dependency 변경 직후 직접 적용하지 않고 시뮬레이션과 저속 검증을 먼저 수행한다.

## 개인정보와 보안

- `.env`, API key, Hugging Face token, Notion token은 기준선에 포함하지 않는다.
- 모델 manifest에는 token이 아닌 공개 identifier, local snapshot ID, hash만 기록한다.
- 카메라 이미지와 실행 output은 Git에 추가하지 않는다.
